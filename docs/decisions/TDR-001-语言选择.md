# TDR-001：编程语言选择

> **状态**：已决策
> **日期**：2026-08-04
> **决策者**：项目作者 + GitHub Copilot 辅助分析

---

## 背景

项目需要构建一个工业软件中继适配层（codex-relay），核心组件包括：
- **Core**：通用数据模型、动作执行引擎、校验框架
- **MCP Server**：将 Core 暴露为 Codex 可调用的工具接口
- **Adapters**：对接四类工业软件（KiCad / STM32 / TI / SolidWorks）

需要在项目启动前确定主要编程语言。

---

## 候选方案

### 方案 A：Python 3.11+

### 方案 B：TypeScript (Node.js 20+)

### 方案 C：Rust

## 详细分析

### KiCad 集成（决定性因素）

KiCad 提供 **pcbnew Python 模块**，可直接在 Python 中操作 PCB：
```python
import pcbnew
board = pcbnew.LoadBoard("project.kicad_pcb")
# 导出 Gerber、跑 DRC、操作元件...
```
这是 CLI 之上的更优路径（API > CLI）。TypeScript 和 Rust 均无法直接使用此能力。

### STM32 工具链

Python 生态有：
- `pyocd`：ARM Cortex 调试/烧录
- `stm32loader`：UART bootloader
- `stlink` Python 绑定

这些库封装了底层 CLI，提供更好的错误处理和结构化输出。

### MCP Server

Python MCP SDK (`mcp`) 和 TypeScript MCP SDK (`@modelcontextprotocol/sdk`) 均成熟可用。Python 版本 API 简洁，足够本项目使用。

### 类型安全

Python 3.11+ 配合 `pydantic` + `mypy`/`pyright` 可达到工程可接受的类型安全水平。虽然不如 TypeScript/Rust 原生类型系统，但配合严格的 linting 配置可以弥补。

---

## 决策

**选择 Python 3.11+**

### 核心理由

1. **KiCad 的 pcbnew Python API 是无可替代的优势**——这是我们首发目标软件的最强集成路径
2. Python 是工业自动化/EDA 工具链的事实标准脚本语言
3. pydantic 提供工业级的 JSON Schema 校验和序列化
4. AI 辅助编程（Copilot/Kimi）对 Python 的理解和生成质量最高
5. 性能不是本项目瓶颈——瓶颈在外部工业软件的响应时间

### 附加规则

- **最低版本 Python 3.11**（使用 `Self` 类型、`tomllib` 等新特性）
- **强制使用 pydantic v2** 做所有数据模型定义
- **强制 mypy strict mode** 做类型检查
- **所有公共接口必须有 type hints**

---

## 后果

### 正面
- KiCad 适配器可以直接使用 pcbnew，无需子进程调用
- 代码对 AI 辅助编程友好
- 丰富的测试框架（pytest）和 CLI 框架（typer/click）

### 负面
- 如果后续需要 Web UI，需要额外的前端技术栈
- Python 打包（尤其是含 C 扩展的库）在 Windows 上偶有挑战
- 运行时性能不如编译型语言（但非瓶颈）

### 应对措施
- Web UI 不在一期规划内，暂不处理
- Windows 打包使用 `pipx` 或 `uv` 工具链简化依赖管理
- 性能敏感路径（如大规模日志解析）可用 `orjson` 加速
